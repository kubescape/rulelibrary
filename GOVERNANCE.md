# Governance

The Kubescape Rule Library is part of the Kubescape project and follows its
[central governance](https://github.com/kubescape/project-governance/blob/main/GOVERNANCE.md).
That document is authoritative for project governance, including maintainer and
triager eligibility, appointment, and removal. The
[maintainer roster](https://github.com/kubescape/project-governance/blob/main/MAINTAINERS.md)
lists the project's maintainers and triagers.

## Roles and Responsibilities

- **Maintainers** provide project direction, set priorities, review and merge pull
  requests, manage releases, and ensure the quality and stability of the library.
  They also resolve conflicts that contributors cannot resolve themselves.
- **Triagers** organize the issue and pull request backlog, apply labels and
  milestones, request reviews, ask clarifying questions, and reproduce reported
  bugs. They assist with review coordination; merging remains the responsibility
  of maintainers.
- **Community members** contribute code, detection rules, documentation, feedback,
  and other project support. Anyone can participate.

## Proposing Changes and Making Decisions

Discuss proposed changes in an issue in this repository. Once there is consensus,
submit a pull request for maintainer review. Maintainers may merge an approved pull
request; triagers may help organize the discussion and request reviewers.

Contributions must follow the repository's [contribution guidance](README.md#contributing)
and the [Kubescape contributing guide](https://github.com/kubescape/project-governance/blob/main/CONTRIBUTING.md),
including DCO sign-off on commits. Report vulnerabilities through the confidential
process in [SECURITY.md](SECURITY.md).

## Conflict Resolution

Participants should first try to resolve disagreements among themselves. If a
conflict remains unresolved, escalate it to the maintainers. The maintainers' decision
is final under the central governance policy.

All project interactions must follow the
[Kubescape code of conduct](https://github.com/kubescape/project-governance/blob/main/CODE_OF_CONDUCT.md).

## Governance Changes

Proposed changes to project governance follow the same issue discussion, consensus,
and maintainer review process described in the central governance document. Submit
changes to the central policy in the
[project-governance repository](https://github.com/kubescape/project-governance).
Updates to this repository's governance summary should remain aligned with that policy.
