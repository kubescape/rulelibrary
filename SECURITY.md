# Security Policy

The Kubescape Rule Library follows the
[Kubescape security policy](https://github.com/kubescape/project-governance/blob/main/SECURITY.md).

## Reporting a Vulnerability

Report suspected security vulnerabilities in this repository confidentially through
the [Kubescape private vulnerability reporting channel](https://github.com/kubescape/kubescape/security/advisories/new).
Identify `kubescape/rulelibrary` as the affected repository so that the report can be
routed to the appropriate maintainers.

Include the following information where available:

- A description of the vulnerability and its security impact.
- Affected versions or commit identifiers and relevant rule identifiers.
- Steps to reproduce the issue, including a minimal example and relevant configuration.
- Any known mitigations or suggested fixes.

Do not disclose vulnerability details in public issues, pull requests, or discussions
before coordinated disclosure with the maintainers. Avoid including credentials or
other sensitive data in reproduction material.

## Response and Disclosure

Under the central Kubescape security policy, maintainers will respond within seven
working days of a report. If the issue is confirmed as a vulnerability, maintainers
will open a Security Advisory and acknowledge the reporter's contributions. Kubescape
follows a 90-day disclosure timeline.

The central policy also lists
[cncf-kubescape-maintainers@lists.cncf.io](mailto:cncf-kubescape-maintainers@lists.cncf.io)
as another contact. Refer to that policy for the project's current reporting and
disclosure procedures.
